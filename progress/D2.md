# D2 (2026-08-11) — 도서관 관리 시스템 (target-system) 생성

## 목표
- `target-system/`에 eGovFrame 4.x 경량환경 스타일 도서관 관리 시스템 생성
- 완료 기준: mvn compile 성공 / schema.sql MariaDB 실행 성공 / 패키지 구조 준수 /
  전체 컬럼 한글 코멘트 / README.md 작성

## 진행 방식
사용자가 제공한 상세 스펙(패키지 구조, URL 설계, DDL, 업무 규칙, 버그 위치, 규모 가이드)을 바탕으로
먼저 **전체 파일 목록(java 41개)과 DDL 초안을 제시해 승인**을 받은 뒤 생성 시작.
book → member → loan → overdue → cmmn 순서로 도메인 단위 커밋.

## 완료 내역

### 툴링 환경 준비
- JDK: Temurin 17 (winget) 설치
- Maven: winget에 정식 패키지가 없어 Apache 아카이브에서 3.9.9 직접 다운로드 후 로컬 설치,
  이후 프로젝트에 Maven Wrapper(`mvnw`/`mvnw.cmd`) 생성 — 시스템에 Maven 없어도 빌드 가능
- MariaDB: winget으로 12.3.2 설치. **이미 기존 MySQL80 서비스가 3306 포트를 사용 중이어서
  MariaDB는 3307 포트로 분리 설치** (사용자 승인받음). 관리자 권한이 없어 Windows 서비스로
  등록하지 못해, `mariadbd.exe`를 백그라운드 프로세스로 직접 실행하는 방식으로 우회
  (프로토타입 개발 단계라 서비스 자동시작은 불필요하다고 판단)

### 프로젝트 골격
- Maven 프로젝트(`pom.xml`): Spring 5.3.39, MyBatis 3.5.16, mariadb-java-client, commons-dbcp2,
  jackson-databind(일부 AJAX 응답용), slf4j+logback. Java 8 소스/타겟, UTF-8 인코딩 명시
  (플랫폼 기본 인코딩이 MS949라 명시하지 않으면 한글 주석이 깨질 수 있음을 확인하고 대응)
- Spring XML 설정: `web.xml`, `root-context.xml`(DataSource/MyBatis/트랜잭션),
  `servlet-context.xml`(Controller/뷰리졸버)
- 이슈 1건 발견 및 수정: `GlobalExceptionHandler`(`@ControllerAdvice`)가 `servlet-context.xml`의
  `@Controller`전용 include-filter에는 걸리지 않아 컴포넌트 스캔이 안 되는 문제 → include-filter에
  `ControllerAdvice` 어노테이션 추가로 해결

### 도메인 생성 (5계층: Controller/Service/ServiceImpl/Mapper/VO)
- **book**: 도서 + 분류(TB_CATEGORY) 관리, 8개 파일
- **member**: 회원 관리, 7개 파일 (MemberStatus enum 포함)
- **loan**: 대출/반납/연장 핵심 업무 로직, 10개 파일. **의도적 버그 2개 포함**:
  1. `LoanServiceImpl.insertLoan()` — 회원 조회 결과 null 체크 없이 `getMemberStatus()` 호출 → NPE 가능
  2. `LoanServiceImpl.insertLoan()` — 도서 조회는 하지만 `LOAN_YN` 값 검증 로직 누락 → 중복 대출 가능
- **overdue**: 연체 관리, 7개 파일. 연체 상태 일괄 갱신 배치(`refreshOverdueStatus`) 포함
  (loan 도메인에 `LoanMapper.updateLoanStatus()` 메서드 추가로 확장 필요했음)
- **cmmn**: 공통 예외/VO/유틸 9개 파일. 이 단계 완료 후 전체 41개 java 파일 컴파일 가능해짐

### DB
- `db/schema.sql`: 6개 테이블(TB_CATEGORY/TB_BOOK/TB_MEMBER/TB_LOAN/TB_OVERDUE/TB_LOAN_HIST),
  전체 39개 컬럼에 한글 COMMENT. MariaDB(3307)에서 fresh 재실행까지 검증 완료
- `db/seed.sql`: 규모가 커서 서브에이전트에 위임해 생성 — 도서 150 / 회원 80 / 대출 250 /
  연체 60 / 이력 451건. LOAN_YN-대출상태 정합성, 최대 5권 제약, 회원상태-연체상태 정합성을
  직접 SQL로 재검증(불일치 0건 확인). 연체 데이터 중 20건이 2026년 8월(이번 달) 기준으로
  활성 상태라 "이번 달 연체 현황" 데모 질의에 사용 가능

### 검증 결과 (완료 기준 5개 항목)
1. `mvn compile` 성공 (41개 클래스 생성 확인) ✅

## 특이사항 / 다음 세션 참고
- java 파일 최종 41개 — 원래 가이드(60~80개)보다 적음. "의미 없는 빈 클래스 금지" 원칙을 지키기
  위해 억지로 채우지 않았고, 사용자 승인 받고 진행함
- JSP는 최소한(도메인별 목록 1개씩)만 작성, 상세/등록/수정은 AJAX(JSON) 또는 폼 POST 후
  리다이렉트 방식
- MariaDB가 3307 포트에서 **프로세스로만** 떠 있음 (Windows 서비스 미등록, 관리자 권한 필요).
  다음 세션에서 새로 컴퓨터를 재시작했다면 `mariadbd.exe --defaults-file="C:\Program Files\MariaDB 12.3\data\my.ini"`
  를 다시 백그라운드로 띄워야 함
- JAVA_HOME은 세션에 영구 설정되지 않음. mvn 실행 시 매번
  `JAVA_HOME="C:\Program Files\Eclipse Adoptium\jdk-17.0.20.8-hotspot"` 지정 필요
- git 커밋 8건 생성 (골격 → book → member → loan → overdue → cmmn → DB/README)
