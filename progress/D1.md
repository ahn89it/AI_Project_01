# D1 (2026-08-11) — 개발 환경 구축

## 목표
- 환경 확인
- Ollama 설치 + EXAONE 3.5 7.8B 다운로드
- Python 개발 환경 준비

## 완료 내역

### 환경 확인
- GPU: NVIDIA GeForce RTX 4060 Laptop, VRAM 8188MiB — CLAUDE.md 사양과 일치
- Python 3.13.7 (요구사항 3.11+ 충족)
- 디스크 여유공간 약 755GB
- git 2.53.0 설치 확인, 프로젝트 디렉터리는 git 미초기화 상태였음

### Ollama 설치
- winget으로 `Ollama.Ollama` 0.32.8 설치
- 설치 후 백그라운드 서비스로 자동 기동 확인 (`http://localhost:11434`)
- 주의: winget 설치 직후에는 현재 셸 세션의 PATH가 자동 갱신되지 않아 `ollama` 명령을 바로 못 찾는 경우가 있었음. 새 셸에서는 정상 인식됨 (`%LOCALAPPDATA%\Programs\Ollama\ollama.exe`)

### EXAONE 3.5 7.8B 다운로드
- `ollama pull exaone3.5:7.8b` — 4.8GB, 정상 다운로드 완료
- 추론 테스트 (Ollama REST API `/api/generate`):
  - 첫 요청(콜드 스타트, VRAM 로딩 포함): 약 76초
  - 재요청: 약 3.6초, 한국어 질의에 정상 한국어 응답
  - VRAM 사용량: 약 5.4GB / 8GB — 여유가 크지 않음 → 임베딩 모델을 CPU로 분리한 CLAUDE.md 설계가 실제로 필요한 선택이었음을 확인
- 이슈: PowerShell `Invoke-RestMethod`로 한글이 포함된 JSON을 보낼 때 기본 문자열 인코딩이 깨져 모델이 한글을 인식하지 못함 → UTF-8 바이트로 명시 인코딩해 해결. (Python `httpx`/`requests` 사용 시에는 발생하지 않는 문제이므로 실제 서버 코드에는 영향 없음. PowerShell로 API 점검할 때만 주의)

### Python 개발 환경
- `.venv` 가상환경 생성 (Python 3.13)
- `requirements.in`(직접 의존성 목록) 작성 후 설치:
  fastapi, uvicorn[standard], streamlit, chromadb, sentence-transformers, tree-sitter, tree-sitter-java, sqlglot, pymysql, python-dotenv, httpx, pydantic, pytest
- torch는 CUDA 버전 대신 CPU 전용 wheel(`--index-url https://download.pytorch.org/whl/cpu`)로 설치 — GPU는 EXAONE 전용으로 남겨두기 위함
- 설치 완료 후 `pip freeze > requirements.txt`로 버전 고정 (CLAUDE.md 규칙 준수)
- 주요 패키지 import 및 버전 확인 완료 (fastapi 0.141.1, streamlit 1.61.1, chromadb 1.5.9, sqlglot 30.16.0, torch 2.13.0+cpu)

### multilingual-e5-large 임베딩 모델
- `sentence-transformers`로 `intfloat/multilingual-e5-large` 다운로드 (Hugging Face, 약 1.1GB)
- CPU 로드 및 임베딩 테스트: 로드 53.1초, 임베딩 0.34초, 결과 shape (2, 1024) — 정상

### git
- 저장소 초기화 (`git init`)
- `.gitignore` 작성 (.venv/, .claude/, data/, __pycache__/ 등 제외)
- 커밋 3건 생성 (CLAUDE.md/gitignore/requirements.in, requirements.txt, gitignore 보완)
