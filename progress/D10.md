# D10 — 업무 매뉴얼 자동 생성 (우선순위 최하, 반나절 원칙)

## 목표
"완벽한 매뉴얼"이 아니라 "자동 생성되는 그럴듯한 매뉴얼". 검증 1(업무규칙 포함)과
검증 4(무할루시네이션)만 통과하면 종료, 문장 어색함은 허용.

## 완료 내역

### server/services/manual_builder.py
- `list_urls()`(D5)로 전체 URL을 도메인별(book/member/loan/overdue)로 그룹핑
- URL 단위로 `get_chain()`(D5) → IMPL_METHOD 코드+한글 주석+관련 테이블을 컨텍스트로 구성 →
  `llm.chat()`(D7) 1회 호출로 처리 절차 생성 (도메인 전체가 아니라 URL 단위로 쪼개서
  실패해도 부분 재생성 가능하게 함, 스펙 지시대로)
- 진행 콜백(URL 단위, D11 UI 연결용) + 파일 캐시(`data/manuals/_procedure_cache.json`,
  이미 생성된 URL은 재사용)
- 부록 "테이블 정의서"는 LLM 호출 없이 `schema_catalog`에서 곧바로 Markdown 표로 생성
  (심사위원에게 "문서 두께감"을 싸게 주는 장치 — tip 3 그대로 적용)
- 도메인당 URL 6~7개를 22개 고정 URL에 대한 한글 제목 매핑표(`_TITLE_OVERRIDES`)로 처리
  (LLM에 제목까지 맡기지 않음 — 시스템이 4개 도메인·22개 URL로 고정돼 있어 표 하나로 충분)

### server/services/prompts.py — MANUAL_SYSTEM_PROMPT
번호 목록 3~7단계, 업무 용어, 검증 규칙(거부 조건) 포함, "코드에 없는 절차 금지" 지시.

### server/routers/manual.py
- `POST /api/manual/generate {"domain": "loan"|"all"}`, `GET /api/manual/latest`(백업본 표시용)

## 실전에서 발견한 할루시네이션 2건과 해결 (검증 4 정독 중 발견)

### 1. "다른 메서드의 규칙을 지금 메서드에 있는 것처럼" 착각
`selectLoanDetail`(단순 조회, null 체크만 있음) 매뉴얼에 "연체 중인 회원의 경우 대출 정보
조회가 거부될 수 있습니다"라는 문장이 생겼는데, 실제 `LoanServiceImpl.selectLoan()` 코드에는
그런 로직이 전혀 없음(같은 클래스의 다른 메서드 `checkLoanable`에 있는 규칙을 혼동한 것으로
추정). 프롬프트에 "다른 메서드의 규칙을 지금 설명하는 코드에 있는 것처럼 쓰지 말 것"을
명시해 해결 — 재생성 후 사라짐.

### 2. "대출" 단어의 도메인 혼동 — 존재하지 않는 "대출 금액" 반복 언급
`selectLoanList`(순수 위임, `return loanMapper.selectLoanList(searchVO);` 한 줄뿐이고
if/throw가 전혀 없음) 매뉴얼에 "대출 기간, **대출 금액 범위**, 대출 상품 유형" 같은, 우리
도서관 시스템에는 존재하지 않는 **은행 대출** 개념이 반복적으로 등장. "대출"이라는 단어가
책 대출과 금융 대출 양쪽에 다 쓰이다 보니, 실제 코드에 설명할 내용이 거의 없는(순수 위임)
상황에서 모델이 학습 데이터의 금융 도메인 쪽으로 빈 공간을 채운 것으로 보임.
- 1차 시도(프롬프트에 "금액/수수료 지어내지 말 것" 명시)로도 재현됨 — **프롬프트 튜닝만으로
  해결 안 됨**
- 구조적으로 대응: `if`/`throw`가 전혀 없는(=검증·분기 로직이 없는) 순수 위임 메서드는
  애초에 LLM을 호출하지 않고 정형 문구("입력된 검색 조건에 맞는 데이터를 조회합니다 / 조회된
  결과를 반환합니다")로 대체. 22개 URL 중 7개가 여기 해당(주로 `select*List`류) — 부수
  효과로 전체 생성 시간도 단축됨 (LLM 호출 15건으로 감소)
- 알려진 트레이드오프: 이 휴리스틱은 조건문 없이 반복문만 있는 배치성 메서드
  (`OverdueServiceImpl.refreshOverdueStatus`, for문 2개·조건문 0개)도 "단순 위임"으로
  분류해 정형 문구를 붙임 — 할루시네이션은 아니지만(사실을 지어내진 않음) 설명이 다소
  단조로워짐. 대상이 1개 URL뿐이고 검증 대상(대출·반납)도 아니라 오늘은 그대로 둠 (V2 개선
  대상으로만 기록)

## 검증 결과

1. **loan 도메인 생성 → 업무규칙 포함**: `insertLoan`/`checkLoanable` 절차에 회원상태 확인,
   연체 확인(`MemberStatus.NORMAL` 아님→거부), 대출 한도 확인(5권 초과 시 거부), 도서 상태
   변경(대출중↔대출가능), 대출/반납/연장 이력 기록이 전부 업무 용어로 정확히 포함됨 ✅
2. **전체(all) 1회 생성**: 84.4초 (URL 22개 = LLM 호출 15건 + 정형 문구 7건),
   `data/manuals/manual_20260813T220640_034848.md`에 저장 →
   `target-system/demo/backup_manual.md`로 복사 (시연 백업본 확정)
3. **부록 테이블 정의서**: 6개 테이블(TB_BOOK/TB_CATEGORY/TB_LOAN/TB_LOAN_HIST/TB_MEMBER/
   TB_OVERDUE) 전부 + 전 컬럼 한글 코멘트 포함 확인 ✅
4. **무할루시네이션 정독(대출·반납 6개 기능 전체)**: 위 2건을 발견해 수정한 뒤 재검증 —
   `checkLoanable`/`insertLoan`/`selectLoanDetail`/`selectLoanList`/`updateExtend`/
   `updateReturn` 전부 코드와 대조해 지어낸 절차 없음 확인 (실제 메서드 호출명까지 정확히
   인용: `overdueMapper.insertOverdue`, `memberMapper.updateMemberStatus` 등) ✅

## 시연 전략 (tip 2 반영)
- 시연 각본: **loan 도메인만 실시간 생성**(캐시 없이 처음부터면 약 1분, 이미 캐시돼 있으면
  수 초) 보여주고, 전체 문서는 `target-system/demo/backup_manual.md`를 펼쳐서 보여주는
  방식으로 진행
- `GET /api/manual/latest`가 이 백업본 표시 역할을 겸함 (D11에서 UI 버튼 하나로 연결 가능)
