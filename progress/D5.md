## 완료 내역

### ddl_parser.py
- sqlglot(`dialect="mysql"`, sqlglot에는 별도 mariadb dialect가 없어 mysql로 대체 — MariaDB
  DDL과 거의 호환)로 CREATE TABLE을 파싱. 테이블 코멘트(`SchemaCommentProperty`), 컬럼 코멘트
  (`CommentColumnConstraint`), PK(`PrimaryKey`), FK(`Constraint`+`ForeignKey`+`Reference`),
  기본값(`DefaultColumnConstraint`) 전부 sqlglot 표현식 트리에서 정확히 추출 확인
  (사전에 인터랙티브로 트리 구조를 찍어보고 실제 필드명을 검증한 뒤 구현)
- sqlglot 파싱이 실패하는 테이블에 대비한 정규식 보조 경로도 포함 (스펙 요구사항, 이번
  데이터에서는 발동하지 않음 — 6개 테이블 전부 sqlglot으로 정상 파싱됨)
- `get_schema_text()`: 39개 컬럼 전부 한글 코멘트 포함해서 읽기 좋은 텍스트로 출력 확인

### callgraph.py
- 노드 7종(URL/CONTROLLER_METHOD/SERVICE_METHOD/IMPL_METHOD/MAPPER_METHOD/SQL/TABLE),
  엣지 5종(HANDLES/CALLS/IMPLEMENTS/EXECUTES/REFERENCES)으로 SQLite 스키마 설계
- 연결 로직: 주입필드(injected_fields) + 호출식(receiver.method()) 조합으로 CALLS 엣지 생성.
  1차로 필드 타입 직접 매칭, 실패 시 스펙에서 제안한 **eGov 명명 관례 폴백**(변수명 앞글자
  대문자화 → 클래스명 추정, `bookService`→`BookService`)을 적용 — target-system이 관례를
  정확히 지켜 생성되어 있어서 실제로는 필드 매칭만으로도 대부분 해결되고 폴백은 보조 역할
- Service 인터페이스→구현체는 `implements` 관계 + 동일 메서드명 매칭으로 IMPLEMENTS 엣지
- 같은 클래스 내부 호출(receiver가 null 또는 "this")도 CALLS 엣지로 저장
- VO/ETC 계층은 애초에 그래프 노드로 만들지 않아서, getter/유틸 호출(`loanVO.getMemberId()`,
  `DateUtil.calcDueDate()` 등)이 "타겟 클래스는 있지만 계층이 아님"으로 자연스럽게 걸러짐
  (unresolved가 아니라 ignored로 분류)
- `python -m analyzer.callgraph` 실행 시 기존 graph.db 삭제 후 재생성(멱등성), 같은 커넥션에
  ddl_parser의 schema_catalog까지 함께 채움

## get_chain("/loan/insertLoan.do") 실제 출력 요약
```
URL /loan/insertLoan.do (POST)
 └─HANDLES→ LoanController.insertLoan (L52-56)
     └─CALLS→ LoanService.insertLoan (interface)
         └─IMPLEMENTS→ LoanServiceImpl.insertLoan (L58-97)
             ├─CALLS→ MemberMapper.selectMember      → SQL(select) → TB_MEMBER
             ├─CALLS→ LoanMapper.selectLoanCountByMember → SQL(select) → TB_LOAN
             ├─CALLS→ BookMapper.selectBook           → SQL(select) → TB_BOOK, TB_CATEGORY
             ├─CALLS→ LoanMapper.insertLoan           → SQL(insert) → TB_LOAN
             ├─CALLS→ BookMapper.updateLoanYn         → SQL(update) → TB_BOOK
             └─CALLS→ LoanMapper.insertLoanHist       → SQL(insert) → TB_LOAN_HIST
```
노드 21개, 엣지 22개. "회원 상태 확인 → 대출권수 확인 → 도서 조회 → 대출 등록 → 도서 상태
변경 → 이력 기록" 업무 흐름이 그대로 SQL/테이블까지 이어짐 — D7 Q&A가 "대출 처리 절차를
설명해줘"에 답할 때 이 체인이 그대로 근거 자료가 됨을 직접 눈으로 확인.
