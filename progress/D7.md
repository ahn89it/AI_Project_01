### server/services/context_builder.py — 오늘의 핵심
- top-5 검색 → 상위 3개 히트를 `full_chain_for_node`로 확장 → 후보 노드에 우선순위(tier)
  부여(히트 자체 > 하류 > 상류 > 기타) → 문자수 예산(5000토큰≈1만자 추정) 안에서 tier 순으로
  코드 블록 조립
- **실제 첫 테스트에서 발견한 빈틈**: "회원은 몇 권까지 빌릴 수 있나요?" 질문에 LLM이
  `LibraryConstants.MAX_LOAN_COUNT`라는 상수 *이름*만 언급하고 "구체적인 숫자 값은
  명시되지 않았다"며 얼버무림 — 실제로 `LibraryConstants`(cmmn.util, ETC 계층)는 호출그래프
  노드가 아니라서 컨텍스트에 값이 전혀 안 들어갔던 것. 컨텍스트 조립 로직에 "히트 코드 안에서
  `ClassName.CONSTANT` 형태로 참조되는 작은 ETC 클래스(상수/enum)를 자동으로 함께 담는" 로직을
  추가해서 해결 → 재질의 시 "최대 5권"으로 정확히 답변하는 것 확인
- references는 LLM 출력에서 파싱하지 않고 context_builder가 실제로 프롬프트에 넣은 코드
  기준으로 만듦 (스펙 원칙 그대로) — 그래서 LLM이 답변 형식을 안 지켜도 API의 근거 목록
  자체는 항상 사실

### server/services/prompts.py — 실전에서 두 번 더 강화
1차 시스템 프롬프트(3단 구조 + 할루시네이션 금지)로 첫 테스트를 돌려보니, **본문 설명은
정확한데 "예시 코드"랍시고 실제로 없는 메서드(`handleOverdue`, `MemberStatus.OVERDUE`,
`LoanResult` 등)를 지어내 코드블록으로 끼워 넣는 패턴**을 발견 (Q2, Q3에서 재현).
근거 인용 태그가 안 붙은 "설명용" 코드였어서 references API 필드는 영향 없었지만, 답변
텍스트 자체의 신뢰성 문제라 튜닝 순서 ①(시스템 프롬프트 강화)을 두 단계로 적용:
1. "코드를 지어내지 말고 있는 그대로 인용하라" — 부분적 효과, 여전히 재현됨
2. **"답변에 코드 블록(```)을 아예 쓰지 마라"로 강화** — 5개 중 4개(Q1,Q2,Q4,Q5)에서
   완전히 해결. Q5는 오히려 코드 블록을 썼지만 이번엔 **실제 코드 그대로**(BookServiceImpl
   .updateBook/selectBook) 인용해서 문제 없음
- Q3(연체 회원 대출 가능 여부)만 재현율이 남아 있었음 (`MemberStatus.OVERDUE`라는 존재하지
  않는 enum 값을 계속 언급). temperature 0.2→0.1로 낮춰 재시도하니 실제 코드
  (`return new LoanResultVO(false, "연체 중이거나 정상 상태가 아닌 회원입니다.", "OVERDUE_MEMBER")`)를
  정확히 인용 — 다만 이건 1회성 확인이라 기본 temperature는 스펙 지시대로 0.2 유지
  (`OVERDUE_MEMBER`는 실제 코드의 문자열 상수라 이 자체는 할루시네이션 아님, 헷갈렸던 건
  "OVERDUE"를 enum 값처럼 서술한 프로즈 쪽)
- CLAUDE.md 원칙대로 모델 교체는 검토하지 않음 — 전부 프롬프트/컨텍스트 조립 레벨에서 해결
