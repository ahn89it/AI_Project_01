# D12 — 시연 안정성 검증 & 시나리오 확정 (개발 금지일)

## 목표
새 기능/리팩토링 없이, 시연 질문을 반복 실행해 안정성을 검증하고 5분 시연 시나리오를
확정한다. 오늘의 산출물은 코드가 아니라 "시연 시나리오 확정 문서"와 "10회 반복 테스트
결과표".

## 완료 내역

### 1. scripts/demo_test.py (반복 테스트 도구)
이미 검증된 API(FastAPI)를 `requests`로 직접 호출해 성공률·응답시간을 측정하는 스크립트.
분석/AI 로직 없음. 카테고리별 실행:
- A. Q&A 5개 질문 × 10회 (D7 qa_candidates.md 전량) — 키워드 포함 여부 + references 존재로 판정
- B. 장애 진단 × 10회 — error_location이 BUGS.md 버그1 위치(line 63)와 정확히 일치 + "null" 언급
- C. Text-to-SQL 4개 질문 × 10회 — guard 통과 + row_count 기대 범위
- D. 안전성 2개 × 5회 — 100% 차단(가드 400 또는 실행단계 0건) 확인
- E. 매뉴얼(loan) × 3회 — 매 시도마다 캐시를 비워 진짜 재생성 3번 반복, 검증 규칙 키워드 포함
- 실패 건은 `target-system/demo/failures/*.json`에 요청/응답 전문 저장

### 2. 실행 중 발견/수정한 문제 (스크립트 자체 버그, 5분 이내 안전한 수정 — 허용 범위)
Windows 콘솔 기본 코드페이지(cp949)로 em-dash(—) 등 특수문자를 stdout에 출력하면
`UnicodeEncodeError`로 스크립트가 즉시 죽는 문제 발견 (표시 깨짐이 아니라 실제 크래시).
`sys.stdout.reconfigure(encoding="utf-8")`로 고침. 이후 113회 전체 정상 완주.

### 4. 자동 테스트가 놓친 것 — 수동 후속 검증 (코드 수정 없이 보고만)
- **"정지 상태인 회원 목록"은 자동 판정 10/10이지만 실제로는 결함**: 모델이 스스로
  `LIMIT 10`을 붙여, 실제 21명 중 10명만 보여주고 "더 있다"는 안내가 없음. 시연 확정
  질문에서 제외.
- **Q&A 코드블록 금지 규칙이 50회 중 1회 깨짐**: D7에서 금지한 ```java 코드 블록이
  재등장하며 실재하지 않는 메서드(`handleOverdue`, `MemberStatus.fromCode`)를 지어냄.
  references API 필드 자체는 항상 정확(파싱이 아니라 context_builder가 만든 실제 코드
  기준)이라 화면상 치명적이진 않음.
- **"지금 대출 중인 책이 몇 권" 실제 값 재확인**: `row_count==1`만 자동 확인했던 걸 수동
  검증 — 실제 반환값 80(D9 정답)과 일치 확인.
- 콜드스타트: 이번 테스트는 서버가 이미 웜업된 상태라 관찰되지 않음(전 항목 "콜드스타트
  의심" 열이 "-"). 시연 당일 완전 콜드 부팅 직후엔 여전히 느릴 수 있어 워밍업 질의 체크리스트
  유지.

### 5. target-system/demo/scenario.md (5분 시연 대본 확정)
확정 질문/입력:
- Q&A: "도서 대출은 어떻게 처리되나요?" (10/10, 평균 24.0초, 근거 15건)
- 진단: `error_log_1.txt` (10/10, 평균 27.3초, line 63 매번 정확)
- SQL: "이번 달 연체 회원 목록과 연체 일수를 보여줘" (10/10, 평균 8.4초, 매번 20건)
- 위험 SQL: "회원 테이블을 전부 지워줘" (5/5 100% 차단)
- 매뉴얼: loan 도메인 최근 생성본(백업본 사용 — 콜드 생성 44~50초로 30초 예산 초과)

시간대별 대본(0:00~4:45), 실패 대비 플랜 B, 사전 세팅 체크리스트 포함.

### 6. target-system/demo/text_backups/ (텍스트 기반 백업 7건)

B 절에서 각 파일로 연결.
