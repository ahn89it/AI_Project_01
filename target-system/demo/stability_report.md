## 추가 확인 사항 (자동 테스트 이후 수동 검증, 코드 수정 없이 보고만 함)

### 1. "정지 상태인 회원 목록" — 10/10이지만 결과가 조용히 잘림
자동 테스트는 `row_count>=1`만 확인해 10/10 통과했지만, 생성된 SQL이 매번
`LIMIT 10`을 자체적으로 붙인다 (가드가 붙인 게 아니라 EXAONE이 스스로 생성).
실제 DB에 "정지 상태인 회원이 총 몇 명인지" 별도 질의해보니 진짜 총원은 **21명**으로,
화면에는 그중 10명만 표시되고 "더 있다"는 안내가 없다. 틀린 답은 아니지만(WHERE 조건은
정확) 심사위원이 "이게 전부인가요?"라고 물으면 애매해질 수 있음 — 시연 때는 "상위
10명만 표시됩니다"라고 구두로 짚거나, 다른 확정 질문으로 교체하는 걸 권장.

### 2. Q&A 코드블록 금지 규칙이 가끔(50회 중 1회) 깨짐
"책을 반납하면...무슨 일이 일어나나요?" 8번째 시도의 실패 원인은 키워드 누락이었지만,
답변 전문을 열어보니 D7에서 이미 금지했던 ```java 코드 블록이 다시 등장했고, 그 안에
`handleOverdue()`, `MemberStatus.fromCode()` 같은 실제 코드에 없는 메서드를 지어냄
(references API 필드 자체는 여전히 정확 — LLM 출력에서 파싱하지 않고 context_builder가
실제 코드로 만들기 때문에 화면의 "근거" 목록은 안전함). 50회 Q&A 중 육안 확인은 이
1건뿐이라 빈도는 낮지만, "코드블록 금지" 프롬프트가 100% 강제는 아니라는 뜻이므로 시연 때
답변에 코드블록이 뜨면 당황하지 말고 "근거 코드" expander로 화제를 돌릴 것.

### 3. "지금 대출 중인 책이 몇 권인지" — 실제 값 재확인
자동 테스트는 `row_count==1`만 확인했는데, 수동으로 한 번 더 호출해 실제 반환값이
**80**(D9에서 확정한 정답)임을 재확인함. 안심하고 확정 질문으로 사용 가능.
